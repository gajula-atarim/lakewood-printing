Executive Summary

Every audit issue is fixed except one that needs your social media links

All issues in the baseline audit have been worked through on the live site. Every high- and medium-priority finding is fixed. The one exception is the placeholder social media icons: they link nowhere or to generic Facebook, Instagram and Pinterest home pages, and they stay as they are until Lakewood Printing supplies its real profile links.

The site's design, page addresses, navigation and contact form are unchanged. Screenshots taken before and after show the Home and Services pages are pixel-identical apart from one button label. On the other pages, the only visible change is the extra paragraphs of copy.

How the results were measured

  • Page audits on all five pages before and after (on-page score, titles, descriptions, heading tree, word count, social tags).
  • Lighthouse: SEO on all five pages, plus Performance, Accessibility and Best Practices on the home page.
  • A server-side check of the rendered pages: status codes, headings, image alt text, links, PHP errors, response headers, file content types, the sitemap and robots.txt.
  • Full-page screenshots of every page before and after, desktop and mobile, compared pixel by pixel.

Screaming Frog was not re-run for this report. A re-crawl with the same settings as the baseline will confirm these results in the original tool. See Section 15.

What we also found and fixed along the way

  • Images were loading from the old staging server. Background images, social preview images and stored page data still pointed to lakewood-printing.stagingsea.com. If that server had gone offline, those images would have broken. All 350 references now point to lakewood.net.au, and none remain on the rendered pages.
  • The "bad content type" files were JavaScript files sent with an outdated type (application/x-javascript). They are now sent as application/javascript.
  • Social share previews used scraped page text. Facebook, LinkedIn and other link previews showed jumbled on-page text such as "SOLUTIONS We offer end-to-end solutions… find out more". They now show each page's written title and description.
Technical SEO

Server and security configuration

The headers were added in one clearly labelled block in the server's .htaccess file, so they apply to every page, image and file on the site. The Content-Security-Policy is deliberately permissive, so the page builder and the contact form keep working, and it still allows Atarim's visual feedback tool to load the site.

Next Steps

What is left, and what we recommend next

Needed from Lakewood Printing

  • Your Facebook, Instagram and Pinterest page addresses, or confirmation that any of these don't exist. The icons in the footer, on the contact page and in the mobile menu currently link nowhere or to the generic sites. Once you send the addresses we will link them, or remove the icons you don't use. This clears the last failing Lighthouse SEO check and the remaining unsafe-link findings.
  • Access to Google Search Console, or a Google account to set it up under, so the new sitemap can be submitted and indexing tracked.
Now

Confirm in Screaming Frog

  • Re-crawl with the baseline settings, with XML sitemap crawling turned on
  • Export Issues Overview and compare it with the baseline CSV
Next

Page speed

  • Home page performance: 66 / 100 (LCP 3.2 s, server response 890 ms)
  • The server runs LiteSpeed, so the LiteSpeed Cache plugin is the natural fix
  • Longer cache lifetimes for images and files
Recommended

Content polish

  • Correct the "Calanders" spelling on About Us
  • Consider more descriptive H1s. They currently match the menu labels, such as "Services"
  • Add a 1200×630 social share image. The current one is a thin 854×135 banner
4–8 weeks

Measure results

  • Indexed pages, impressions and clicks in Search Console
  • Keyword rankings for the agreed target terms
  • Enquiries from organic search

Rankings and traffic do not change straight away. Google first has to re-crawl and re-index the updated pages, which usually takes several weeks.

Site safety and rollback

  • A full database backup was taken before any change and stored outside the public web folder.
  • Each edited page was saved through the page builder's own revision system, and its original data was also kept separately.
  • The server configuration change is one clearly labelled block, and the previous file was backed up.
  • Checked after the changes: all pages load, the contact form is present, no PHP errors appear, every script and stylesheet loads with a valid content type, and desktop and mobile screenshots match the original design.
Full change log
  • Installed and configured Yoast SEO. Disabled author, date and post-format archives; set category, tag, attachment and Elementor template pages to noindex; set the organisation name to Lakewood Printing.
  • Wrote titles and meta descriptions for the 5 pages.
  • Set "Hello world!" (post 1) to draft.
  • Added alt text to 23 media library images.
  • Fixed heading levels on all 5 pages, keeping the original typography and colours.
  • Changed "find out more" to "Explore our services" on Home and About.
  • Gave the header's mobile menu button the label "Menu", visually hidden.
  • Added rel="noopener" to the flipbook link.
  • Added 8 factual paragraphs across About, What We Print and Contact.
  • Replaced 350 staging-domain references (lakewood-printing.stagingsea.com → lakewood.net.au) in page data and settings.
  • Added a "Lakewood SEO Security Headers" block to .htaccess: 5 security headers plus the JavaScript content type.
  • Cleared the page builder and object caches.
